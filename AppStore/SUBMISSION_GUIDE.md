# Tennis Score — First-Time App Store Submission Guide

This is a complete, beginner-friendly walkthrough for publishing **Tennis Score** (bundle id `com.efremov.tennisscore`, version 1.0.0) to the App Store. Follow the steps in order. Every command and file path below is real and matches this repository.

Before you start, sanity-check that you have:
- A Mac with **Xcode 26.3** installed (you do).
- This repo at `/Users/colds1emens/tennis_app`.
- The release helpers already present: `Makefile`, `AppStore/ExportOptions.plist`, and the six 6.9" screenshots in `AppStore/screenshots/` (1320×2868, verified).
- The encryption + orientation + iPhone-only settings are already declared in `project.yml` — you do **not** need to edit any plist by hand.

---

## Step 1 — Enroll in the Apple Developer Program ($99/year)

You cannot ship to the App Store without a paid membership (the free account only signs apps onto your own device).

1. Go to <https://developer.apple.com/programs/enroll/> and sign in with the **Apple ID** you want to own this app.
2. Enroll as an **Individual** (simplest for a solo developer; uses your legal name as the seller) or as an **Organization** (requires a D-U-N-S number — only if you have a registered company). Individual is fine for a free app like this.
3. Pay the **$99/year** fee. Approval is usually minutes to ~48 hours.
4. **Find your Team ID** (you'll need this 10-character code for archiving):
   - Sign in at <https://developer.apple.com/account>.
   - Click **Membership details** (left sidebar).
   - Your **Team ID** is the 10-character alphanumeric code (e.g. `AB12CD34EF`). Copy it — this is the value you pass as `TEAM_ID=` in Step 4.

> Tip: the same Team ID is shown in Xcode under **Settings → Accounts → (your team) → Manage Certificates**.

---

## Step 2 — Create the app record in App Store Connect

1. Go to <https://appstoreconnect.apple.com> and sign in with the **same Apple ID** you enrolled with.
2. Open **My Apps** → click the **+** (top left) → **New App**.
3. Fill the dialog:
   - **Platforms:** iOS
   - **Name:** `Tennis Score` (this is the public App Store name; must be unique across the store — if taken, try `Tennis Score — Match & 105`)
   - **Primary language:** English (U.S.)
   - **Bundle ID:** select `com.efremov.tennisscore`. If it's not in the dropdown, register it first at <https://developer.apple.com/account/resources/identifiers/list> → **+** → **App IDs** → **App** → Description `Tennis Score`, Bundle ID **Explicit** = `com.efremov.tennisscore`. (No capabilities/entitlements are needed — this app uses no push, no iCloud, no sign-in.)
   - **SKU:** any internal string you like, e.g. `tennisscore-1` (never shown to users).
   - **User Access:** Full Access.
4. Click **Create**. The app record now exists in a *Prepare for Submission* state.

## Step 3 — Set the signing Team and enable Automatic signing in Xcode

The project is generated by XcodeGen, so first regenerate the Xcode project, then open it.

```bash
cd /Users/colds1emens/tennis_app
make setup     # installs xcodegen if needed and regenerates TennisScore.xcodeproj
open TennisScore.xcodeproj
```

In Xcode:
1. Select the **TennisScore** project in the navigator (top blue icon) → select the **TennisScore** target → **Signing & Capabilities** tab.
2. Check **Automatically manage signing**.
3. Set **Team** to your Apple Developer team (the one with the Team ID from Step 1). If it's not listed, go to **Xcode → Settings → Accounts → +** and sign in with your developer Apple ID, then return.
4. Confirm **Bundle Identifier** reads `com.efremov.tennisscore`. Xcode will provision automatically and show a green checkmark.

> Note: `project.yml` ships with `CODE_SIGNING_ALLOWED: "NO"` (so CI typecheck builds stay unsigned). That's fine — the `make archive` target explicitly overrides it to `CODE_SIGNING_ALLOWED=YES` and `CODE_SIGN_STYLE=Automatic` for the release build, and the Xcode GUI uses your Signing & Capabilities settings. Either path signs correctly.

## Step 4 — Build the release archive and upload

You have **two equivalent paths**. Pick one. The CLI path is faster and is what this repo is set up for; the GUI path is the classic Xcode flow.

### Path A — Command line (recommended, uses the repo Makefile)

From the repo root, run these in order, substituting your real 10-character Team ID:

```bash
cd /Users/colds1emens/tennis_app

# 1) Build and create the signed Release archive
make archive TEAM_ID=AB12CD34EF
#    → produces build/TennisScore.xcarchive

# 2) Export a signed App Store .ipa from that archive
make ipa TEAM_ID=AB12CD34EF
#    → produces build/ipa/TennisScore.ipa
```

What these do under the hood:
- `make archive` runs `xcodebuild ... -configuration Release -destination 'generic/platform=iOS' clean archive` with `DEVELOPMENT_TEAM`, `CODE_SIGN_STYLE=Automatic`, `CODE_SIGNING_ALLOWED=YES`.
- `make ipa` substitutes your Team ID into `AppStore/ExportOptions.plist` (which already declares `method = app-store-connect`, `signingStyle = automatic`, `uploadSymbols = true`) and runs `xcodebuild -exportArchive` into `build/ipa/`.

**Upload the .ipa with Transporter:**
1. Install **Transporter** (free) from the Mac App Store: <https://apps.apple.com/app/transporter/id1450874784>.
2. Open Transporter, sign in with your developer Apple ID.
3. Drag `build/ipa/TennisScore.ipa` (full path `/Users/colds1emens/tennis_app/build/ipa/TennisScore.ipa`) into the window → click **Deliver**.
4. Wait for "Delivery successful". The build then takes ~5–30 min to finish **processing** in App Store Connect before it can be selected.

### Path B — Xcode GUI (Organizer)

1. In Xcode, set the run destination at the top to **Any iOS Device** (Product menu → Destination → **Any iOS Device (arm64)**). You cannot archive while a Simulator is selected.
2. **Product → Archive**. Wait for the build.
3. The **Organizer** window opens automatically. Select the new archive → **Distribute App** → **App Store Connect** → **Upload** → keep the defaults (Automatic signing, include symbols) → **Upload**.
4. Same as Path A, wait for the build to finish processing in App Store Connect.

> Both paths upload the **same** build (version 1.0.0, build 1, as set by `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` in `project.yml`).

## Step 6 — Set App Privacy to "Data Not Collected"

1. In the app record, open **App Privacy** (left sidebar) → **Get Started** (first time).
2. When asked "Do you or your third-party partners collect data from this app?" choose **No, we do not collect data from this app.**
   - This is accurate: the app is fully offline (zero network calls), uses **SwiftData local-only** storage, and has **no analytics, no tracking, no third-party SDKs, no crash reporting**.
3. **Publish**. Your App Store privacy label will display **Data Not Collected**.

## Step 7 — Answer export compliance (encryption)

This app uses no custom or non-exempt encryption.

- The Info.plist key is **already declared** for you: `INFOPLIST_KEY_ITSAppUsesNonExemptEncryption: "NO"` in `project.yml` (line 33), which bakes `ITSAppUsesNonExemptEncryption = NO` into the built app.
- Because that key is present and set to `NO`, App Store Connect will **not** prompt you with the encryption questionnaire for this build — export compliance is auto-resolved as **exempt / no encryption**.
- If you ever *are* asked: answer **No** to "Does your app use encryption?" (or, if asked the follow-up, that you only use standard exempt encryption like HTTPS — though this app makes no network calls at all).

## Step 8 — Submit for review

1. With the build selected and every section showing a green checkmark (Screenshots, Description, Keywords, Support URL, Build, Age Rating, Pricing, App Privacy), click **Add for Review** → **Submit for Review** (top right).
2. **App Review Information** (fill if prompted):
   - **Sign-in required?** **No** — the app opens straight to the home screen, no account, no login. (This is important: stating "no sign-in" prevents reviewers asking for demo credentials.)
   - **Notes for reviewer** (optional but helpful): *"Fully offline app, no account needed. Classic mode: tap either half of the screen to score, swipe down to undo. '105' mode: tap the large capsule buttons on each side. No network, no data collection."*
   - **Contact info:** your name, phone, email.
3. Confirm and submit.

### What to expect
- Status moves through **Waiting for Review → In Review → (Pending Developer Release or Ready for Sale)**. Apple's median review time is roughly **24–48 hours**, occasionally longer.
- You'll get email notifications at each state change.
- If you chose "Automatically release this version" it goes live once approved; if you chose "Manually release", click **Release** when you're ready.

### Common first-timer pitfalls (avoid these)
- **Wrong screenshot size:** App Store Connect rejects mismatched dimensions. Use the provided 1320×2868 6.9" set — they're already correct.
- **Missing Support URL:** the form won't submit without a reachable one. Have a real page ready.
- **Build not visible:** it must finish *processing* (and you must have selected it) before you can submit — wait 5–30 min after upload.
- **Forgetting to bump build numbers later:** if Apple rejects and you re-upload, increment `CURRENT_PROJECT_VERSION` in `project.yml` (build "1" → "2"), run `make setup` again, then re-archive. App Store Connect refuses a duplicate build number.
- **Crash on launch during review:** test the actual Release archive on a device first (Organizer → Distribute App → "Ad Hoc", or just run the Release scheme) so the reviewer doesn't hit a launch crash.
- **Privacy answer mismatch:** since you declared "Data Not Collected", make sure no analytics/SDK sneaks in later — it's true today and must stay true.

That's it. Once approved and released, **Tennis Score 1.0.0** is live on the App Store.
